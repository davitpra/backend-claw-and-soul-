# Generación de Imágenes IA — Documentación

## Flujo general

```
Usuario hace POST /api/generations
         ↓
GenerationsController → GenerationsService
         ↓
  Crea registro en DB (status: "pending")
  Encola job en Redis (BullMQ)
         ↓
  [BullMQ ejecuta en background]
         ↓
ImageGenerationProcessor.process()
         ↓
  StrategyRegistry.get(style.strategyKey)
         ↓
  DefaultStyleStrategy.execute()
    ├─ 1. OpenAIVisionService.analyzePet(photoUrl)
    ├─ 2. PromptBuilderService.build(template, vars)
    ├─ 3. FalService.generate(model, prompt, params)
    └─ 4. StorageService.upload(buffer) → Cloudinary
         ↓
  GenerationsService.markCompleted(id, result)
  → DB: status="completed", resultUrl, finalPrompt, etc.
```

## Los 4 pasos del pipeline

### 1. Vision Analysis (`OpenAIVisionService`)

Llama a GPT-4o con la foto de la mascota. Devuelve un JSON con los atributos visuales:

```json
{
  "species": "dog",
  "breed": "golden retriever",
  "coatColor": "golden",
  "pose": "sitting",
  "expression": "happy",
  "background": "grass field",
  "distinctiveFeatures": "fluffy tail"
}
```

Se puede desactivar por estilo con `visionEnabled: false` en el modelo `Style`.

### 2. Prompt Builder (`PromptBuilderService`)

Toma el `promptTemplate` del Style en DB y reemplaza los placeholders con los datos del análisis y la mascota:

```
template: "A {coatColor} {breed} named {petName}, watercolor painting"
          ↓
resultado: "A golden golden retriever named Max, watercolor painting"
```

Variables disponibles en el template: `{petName}`, `{breed}`, `{species}`, `{coatColor}`, `{pose}`, `{expression}`, `{background}`, `{distinctiveFeatures}`, `{userPrompt}`.

### 3. Generación con Fal.ai (`FalService`)

Envía el prompt al modelo configurado en el Style (`falModel`). Descarga la imagen resultante como `Buffer`.

```typescript
fal.subscribe("fal-ai/flux/dev", {
  input: {
    prompt: "A golden retriever named Max, watercolor painting",
    image_size: "square_hd",
    num_inference_steps: 28,
  }
})
```

### 4. Subida a Cloudinary (`StorageService`)

Sube el buffer y devuelve la URL pública. La URL se guarda en `Generation.resultUrl`.

## Strategy Pattern — Añadir un nuevo estilo

Cada estilo puede tener un pipeline distinto. El campo `strategyKey` del modelo `Style` en DB determina qué strategy se ejecuta en runtime:

| `strategyKey` | Strategy | Descripción |
|---|---|---|
| `default` | `DefaultStyleStrategy` | Pipeline completo: vision → prompt → fal → cloudinary |
| `anime` | `AnimeStrategy` (futuro) | Sin vision, prompt fijo, modelo SDXL |
| `sketch` | `SketchStrategy` (futuro) | Vision activada, parámetros distintos |

### Cómo crear una nueva strategy

1. Crear `pipeline/strategies/anime.strategy.ts`:

```typescript
@Injectable()
export class AnimeStrategy extends BaseStyleStrategy {
  readonly key = 'anime';

  constructor(
    private fal: FalService,
    private storage: StorageService,
  ) { super(); }

  async execute(ctx: PipelineContext): Promise<PipelineResult> {
    const start = Date.now();
    const prompt = `anime style portrait of a ${ctx.pet.species} named ${ctx.pet.name}`;

    const falResult = await this.fal.generate({
      model: ctx.style.falModel ?? 'fal-ai/aura-flow',
      prompt,
      params: ctx.style.parameters as Record<string, any>,
    });

    const storageKey = `generations/${ctx.generationId}/result`;
    const resultUrl = await this.storage.upload(storageKey, falResult.imageBuffer, falResult.contentType);

    return {
      finalPrompt: prompt,
      falRequestId: falResult.requestId,
      resultUrl,
      resultStorageKey: storageKey,
      processingTimeSeconds: Math.round((Date.now() - start) / 1000),
    };
  }
}
```

2. Registrar en `GenerationsModule` (providers) y en `StrategyRegistry` (constructor).

3. Crear el Style en DB con `strategyKey: "anime"`.

## Configuración del modelo `Style` en DB

Para que una generación funcione, el `Style` necesita estos campos:

| Campo | Tipo | Descripción |
|---|---|---|
| `strategyKey` | `string` | Qué strategy usar (default: `"default"`) |
| `falModel` | `string?` | Modelo de Fal.ai (ej. `"fal-ai/flux/dev"`) |
| `promptTemplate` | `string?` | Template con `{placeholders}` |
| `visionEnabled` | `boolean` | Si se analiza la foto con GPT-4o |
| `parameters` | `Json?` | Parámetros extra para Fal.ai (size, steps, etc.) |

### Ejemplo de Style para Watercolor

```json
{
  "strategyKey": "default",
  "falModel": "fal-ai/flux/dev",
  "promptTemplate": "A {coatColor} {breed} named {petName}, watercolor painting, soft pastel tones, artistic",
  "visionEnabled": true,
  "parameters": {
    "image_size": "square_hd",
    "num_inference_steps": 28
  }
}
```

## Datos persistidos por generación

| Campo en DB | Contenido |
|---|---|
| `status` | `pending → processing → completed / failed` |
| `visionAnalysis` | JSON con lo que detectó GPT-4o |
| `finalPrompt` | El prompt exacto enviado a Fal.ai |
| `falRequestId` | ID del job en Fal.ai (trazabilidad) |
| `resultUrl` | URL pública en Cloudinary |
| `resultStorageKey` | Public ID en Cloudinary |
| `processingTimeSeconds` | Tiempo total del pipeline |
| `errorMessage` | Mensaje de error si `status = "failed"` |

## Variables de entorno requeridas

```bash
OPENAI_API_KEY=sk-...     # Para GPT-4o Vision

```

Configuradas en `src/config/ai.config.ts` y accesibles vía `ConfigService` con el namespace `ai`.

## Endpoints REST

| Método | Ruta | Descripción |
|---|---|---|
| `POST` | `/api/generations` | Crear nueva generación |
| `GET` | `/api/generations` | Listar generaciones del usuario |
| `GET` | `/api/generations/:id` | Obtener una generación |
| `GET` | `/api/generations/:id/status` | Polling de estado (`pending/processing/completed/failed`) |
| `PATCH` | `/api/generations/:id` | Actualizar flags (`isPublic`, `isFavorite`) |
| `DELETE` | `/api/generations/:id` | Eliminar generación |

Todos los endpoints requieren JWT. Documentación completa en `http://localhost:3001/api/docs`.
